## Phase 0: 紧急 Bug 修复（预计 1-2 小时）

> 目标：消除影响正确性的已知 Bug，零风险、立竿见影。

### P0-1. FormModal 双重提交 Bug
- **文件**: `frontend/src/components/FormModal.tsx`
- **问题**: 提交按钮同时有 `onClick={handleSubmit}` 和 `type="submit"`（在 `<form onSubmit={handleSubmit}>` 内），导致点击时触发两次提交
- **修复**: 移除按钮上的 `onClick={handleSubmit}`，仅保留 `type="submit"`

### P0-2. Toast 动画缺失
- **文件**: `frontend/src/index.css`
- **问题**: `Toast.tsx:85` 引用 `animate-[slide-in-right_0.3s_ease]`，但 CSS 中未定义 `@keyframes slide-in-right`
- **修复**: 在 `index.css` 中补充：
```css
@keyframes slide-in-right {
  from { transform: translateX(100%); opacity: 0; }
  to { transform: translateX(0); opacity: 1; }
}
```

### P0-3. NotFound 页面全刷新
- **文件**: `frontend/src/App.tsx`
- **问题**: `<a href="/">` 导致整页刷新
- **修复**: 改为 `<Link to="/">`（从 `react-router-dom` 导入）

### P0-4. GlobalExceptionHandler 缺少 IllegalArgumentException 处理
- **文件**: `src/main/java/com/property/common/GlobalExceptionHandler.java`
- **问题**: `UserServiceImpl.validatePasswordComplexity()` 抛出 `IllegalArgumentException`，被兜底 `Exception` handler 捕获后返回模糊消息
- **修复**: 新增 handler：
```java
@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public Result<Void> handleIllegalArgument(IllegalArgumentException e) {
    log.warn("参数非法: {}", e.getMessage());
    return Result.error(e.getMessage());
}
```

### P0-5. UserServiceImpl 异常类型统一
- **文件**: `src/main/java/com/property/service/impl/UserServiceImpl.java`
- **问题**: `validatePasswordComplexity()` 抛 `IllegalArgumentException` 而非 `BusinessException`
- **修复**: 统一改为抛出 `BusinessException`，保持与其他 Service 一致

### P0-6. Owner 实体 userId 幽灵字段
- **文件**: `src/main/java/com/property/entity/Owner.java`
- **问题**: `userId` 字段在 DB 中无对应列，MyBatis 静默忽略，但 API 文档会暴露该字段
- **修复**: 删除 `userId` 字段（若无关联需求），或在 DB 中添加 `user_id` 列并建立外键

## Phase 1: 安全加固（预计 3-4 小时）

> 目标：将安全性从 7/10 提升至 9.5/10。

### P1-1. 开发配置凭据外部化
- **文件**: `src/main/resources/application-dev.yml`
- **问题**: 硬编码 JWT Secret 回退值、数据库密码、Druid 凭据
- **修复**:
  - 移除 JWT Secret 的默认值，改为 `${JWT_SECRET}`（与 prod 一致）
  - 数据库密码改为 `${DB_PASSWORD:}`（无默认值，启动时报错提醒配置）
  - Druid 凭据改为环境变量：`${DRUID_USER:admin}` / `${DRUID_PASS:}`

### P1-2. pageSize 上限校验
- **文件**: 所有 Controller（OwnerController、EmployeeController、HouseController、FeeController、ParkingController、ComplaintController、RepairController、DutyController）
- **问题**: `pageSize` 无上限，可传 `999999` 导致资源耗尽
- **修复**: 在 Service 层或 Controller 层添加上限：
```java
if (pageSize == null || pageSize < 1) pageSize = 10;
if (pageSize > 100) pageSize = 100;
```

### P1-3. 身份证号 API 脱敏
- **文件**: `src/main/java/com/property/entity/Owner.java`
- **问题**: `idCard` 在 API 响应中完整返回
- **修复方案 A（推荐）**: 创建 `OwnerVO` DTO，使用 `@JsonSerialize` 自定义序列化器，将 `110101199001011234` 显示为 `1101**********1234`
- **修复方案 B（快速）**: 在 Entity 上添加 `@JsonProperty` + 自定义 getter，返回脱敏后的值

### P1-4. Token 吊销机制
- **文件**: 新增 `src/main/java/com/property/controller/AuthController.java` + `src/main/java/com/property/security/TokenBlacklist.java`
- **问题**: 无 `/logout` 端点，Token 24 小时内持续有效
- **修复**:
  - 创建 `TokenBlacklist`（基于 `ConcurrentHashMap` + TTL 过期清理），存储已吊销的 Token JTI
  - 在 `JwtUtil` 生成 Token 时添加 `jti` claim（UUID）
  - 新增 `POST /api/auth/logout`，将当前 Token 的 JTI 加入黑名单
  - `JwtAuthenticationFilter` 校验时检查 JTI 是否在黑名单中
  - 注：生产环境应替换为 Redis 存储

### P1-5. 数据级权限隔离（ABAC 初步）
- **文件**: `src/main/java/com/property/controller/*.java`、`src/main/java/com/property/service/impl/*.java`
- **问题**: USER 角色可查看所有业主的 PII
- **修复方案（分步）**:
  1. `sys_user` 表添加 `owner_id` 列（关联到 `owner.id`）
  2. 创建 `DataPermissionFilter`，在 `/page` 查询时自动注入 `owner_id` 条件
  3. USER 角色只能查看与自己关联的业主数据
  4. ADMIN 角色不受限制

### P1-6. 角色实时校验
- **文件**: `src/main/java/com/property/security/JwtAuthenticationFilter.java`
- **问题**: 角色从 JWT Claims 读取，降级角色后旧 Token 仍有效
- **修复**: 在 `getByUsername` 查询中同时返回角色，与 JWT Claims 对比，不一致时强制使用 DB 中的角色

### P1-7. 安全头补全
- **文件**: `src/main/java/com/property/security/SecurityConfig.java`
- **修复**:
  - 添加 CSP 头：`Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'`
  - 添加 HSTS 头：`Strict-Transport-Security: max-age=31536000; includeSubDomains`

## Phase 2: 架构升级（预计 6-8 小时）

> 目标：将架构设计和代码质量从 7/10 提升至 9.5/10。

### P2-1. DTO 层引入
- **新增文件**: `src/main/java/com/property/dto/` 目录下为每个模块创建 DTO
- **核心 DTO**:
  - `OwnerCreateRequest`、`OwnerUpdateRequest`、`OwnerResponse`
  - `FeeCreateRequest`、`FeeUpdateRequest`、`FeeResponse`
  - 其余模块类似
- **收益**: API 契约与 DB Schema 解耦；敏感字段不暴露；接口文档清晰
- **实施**: Controller 接收 `@Valid @RequestBody XxxRequest`，Service 返回 Entity，Controller 转换为 `XxxResponse`（可用 MapStruct 或手写 Converter）

### P2-2. REST 语义化
- **文件**: 所有 Controller
- **修改**:
  - `POST /add` → `POST /`（或 `POST /api/owner`）
  - `POST /update` → `PUT /{id}`
  - `POST /delete/{id}` → `DELETE /{id}`
  - `GET /get/{id}` → `GET /{id}`
  - `GET /page` → `GET /`（带 Query 参数）
- **注意**: 前端 `api.ts` 的 `crud<T>()` 工厂需要同步修改 HTTP 方法

### P2-3. 泛型 BaseCrudController
- **新增文件**: `src/main/java/com/property/common/BaseCrudController.java`
- **内容**:
```java
public abstract class BaseCrudController<T, S extends BaseService<T, ?>> {
    protected abstract S getService();
    
    @GetMapping("/{id}")
    public Result<T> getById(@PathVariable Integer id) { ... }
    
    @PostMapping
    public Result<Void> add(@Valid @RequestBody T entity) { ... }
    
    @PutMapping("/{id}")
    public Result<Void> update(@PathVariable Integer id, @Valid @RequestBody T entity) { ... }
    
    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Integer id) { ... }
    
    @GetMapping
    public Result<PageResult<T>> page(...) { ... }
}
```
- **收益**: 每个 Controller 从 ~60 行缩减到 ~15 行
